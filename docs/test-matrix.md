## R06 idle single-device network-loss observability (2026-11-20)

**User report:** A is alone in the room, with a static foreground browser page. Disconnecting and restoring network did not create any visible diagnostic change. This is **inconclusive**, not a confirmed server lifecycle failure: browser WebSocket `readyState` can remain `OPEN` when the transport is temporarily black-holed, the previous diagnostic UI primarily displayed peer records, and native WebSocket ping/pong is not visible to page JS.

**Targeted R06 instrumentation:** The joined browser now sends a signal-only `keepalive` with a bounded sequence every **20 s**. The server returns only `keepalive-ack` with that sequence. If the next check still lacks a matching acknowledgement, the client treats the stale WebSocket as disconnected **without waiting for a browser `close` event**, preserves locally selected File objects, and retries the previous room code using the existing exponential backoff. The normal diagnostic summary includes `signalKeepalive` counters and the UI displays signal/roomEntry/heartbeat/disconnect/reconnect information even if `peerCount:0`. These new messages contain **no file bytes, names, addresses, room code or credentials**. Browser timer throttling can delay detection, especially in background tabs; native server heartbeat remains enabled.

**Precise field test (pending):** First refresh the browser to get the deployed code. A alone enters a new room, stages a harmless small file, and opens Diagnostics. Keep the tab **foreground**, without leaving or refreshing. Disconnect network for **at least 60 seconds**, or until the visible heartbeat timeout and reconnect counter change. Then restore the network and check `signalKeepalive.timeouts`, `disconnects`, `reconnectsScheduled`, retained `localSharedFiles` and `roomEntry`. Expect `roomEntry:"created"` only if the server has really detected and removed the old last-member socket; if the original server-side membership never ended, `"resumed"` is legitimate and the result requires more evidence. A 1–5-second Wi-Fi toggle is not a valid negative test. Never share full-debug reports containing network addresses or credentials.

**Coverage:** Node controller tests simulate an idle black-holed WebSocket with no native close and assert watchdog detach, stale-ack rejection, local File retention and automatic same-code entry. aiohttp integration tests validate signal-only acknowledgement and reject invalid or extra fields.
