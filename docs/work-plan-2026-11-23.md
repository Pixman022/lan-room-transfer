# LAN Room — follow-up execution plan (2026-11-23)

**Baseline:** `main` at `251a078d858b5a3c57d5712d7a14757a4c2ec03c` was Live on Render with 22 Python + 95 Node tests passing. This is a **research POC**, not a verified production-grade or physically LAN-only transfer product. This plan is based on [the test matrix](test-matrix.md), [technical risks](limitations.md), [product decisions](PRD-V1.md) and open Issues [#17](https://github.com/Pixman022/lan-room-transfer/issues/17), [#19](https://github.com/Pixman022/lan-room-transfer/issues/19), [#21](https://github.com/Pixman022/lan-room-transfer/issues/21) and [#26](https://github.com/Pixman022/lan-room-transfer/issues/26).

## Non-negotiable constraints

- Keep internet-only HTTPS + **signalling**; actual files and shared file metadata stay on verified WebRTC P2P DataChannels. No server-side files, TURN, arbitrary cloud relay or fallback to transmitting bytes over WebSocket.
- Retain the existing restricted host/host and narrowly verified host/prflx path policy. Do not claim guaranteed same-physical-LAN routing (VPN/routed networks may satisfy host P2P).
- Keep the approved one-button create/join and room-code behavior, room-wide sharing, sequential receive queue, explicit Save, and **immediate room deletion after the final member's actual socket disconnect**.
- Preserve the user's decision to **defer ICE Issue #6**: do not tune the 2+2 retry strategy or selected-path gates under these workstreams.
- Do not mark physical outcomes PASS based solely on mocks, automation, or previously hashed files from a different transfer run. No sensitive user files required for tests.

## Immediate QA command and scope

- Existing: `python -m unittest discover -s tests -q`; `node --test tests/*.test.mjs`.
- New browser CI: `python tests/offline_room_ui.py` (mock peer UI in real Chromium) and `python tests/browser_smoke.py` (real local signalling in two same-host Chromium contexts); **neither** represents two distinct physical devices or validates external routing.
- Real device external digest on Windows: `Get-FileHash -LiteralPath 'C:\\path\\to\\saved.bin' -Algorithm SHA256`. Avoid uploading private files to online hash services.
- Before final product release, make deliberate choices about four-digit code enumeration/room membership abuse, persistence, mobile browser support and what “large files” means.

**Progress discipline:** Only check boxes or close Issues from explicit evidence. Update this plan as implementation and field acceptance proceed.
